  Analysis: UI Text Association Pattern

  After investigating the asset structure, I've identified how Anno 117
  associates UI text to buff attributes:

  Key Finding: Centralized Configuration Assets

  The game uses configuration assets that act as lookup tables mapping
  dataset/enum values to UI text IDs and icons:

  1. ItemInfotipTextFeature (GUID 142928) - Maps ~100+ buff types to display
   text/icons
  2. ItemBalancing (GUID 6000017) - Maps item properties (rarity, niche,
  scope, allocation) to text/icons
  3. BuffConfig (GUID 52456) - Maps buff categories to category names

  Pattern Structure

  Each configuration asset follows this pattern:
  <BuffUpgradeTextAndIcons>
    <BuffProductivity>
      <Text>-6901457306120429160</Text>  <!-- Text ID from texts_english.xml
   -->
      <Icon>29257</Icon>                   <!-- GUID of icon asset -->
    </BuffProductivity>
    <BuffSpeed>
      <Text>-6899782450596141269</Text>
      <Icon>29291</Icon>
    </BuffSpeed>
    <!-- ... 100+ more mappings -->
  </BuffUpgradeTextAndIcons>

  How It Works

  1. Buff attributes are Choice types from datasets (e.g., BuffUpgradeType
  dataset)
  2. Dataset literals match the XML property names in configuration assets
  3. When the game needs UI text for "BuffProductivity", it looks up
  ItemInfotipTextFeature.BuffUpgradeTextAndIcons.BuffProductivity.Text
  4. The text ID references the localized string in texts_english.xml

  Suggested Implementation

  Here's my recommendation for attaching UI text to Attributes with minimal 
  hardcoding:

  1. Create a UITextCache Class

  # assetextractor/parsing/core/uitext.py

  from __future__ import annotations
  import typing as t
  from pathlib import Path
  from dataclasses import dataclass

  if t.TYPE_CHECKING:
      from assetextractor.parsing.core.assets import AssetCache

  @dataclass
  class UITextMapping:
      """Stores UI text and icon for a dataset value."""
      text_id: int | None
      icon_guid: int | None

  class UITextCache:
      """Centralized cache for UI text mappings from configuration 
  assets."""

      # Configuration: Which assets to load and their mapping structures
      CONFIG_ASSETS = {
          142928: {  # ItemInfotipTextFeature
              'path': 'ItemInfotipTextFeature.BuffUpgradeTextAndIcons',
              'mappings': {
                  'BuffUpgradeType': '{}.Text',  # {buff_name}.Text
              }
          },
          6000017: {  # ItemBalancing
              'path': 'ItemConfig',
              'mappings': {
                  'Rarity': 'RarityVisualization.{}.Text',
                  'ItemNiche': 'NicheVisualization.{}.Text',
                  'ItemAllocation': 'AllocationText.{}.Text',
                  'Scope': 'ScopeVisualization.{}.Text',
              }
          },
          52456: {  # BuffConfig
              'path': 'BuffCategory',
              'mappings': {
                  'BuffCategoryType': '{}.Name',
              }
          }
      }

      def __init__(self, assets: AssetCache):
          self.assets = assets
          self.mappings: dict[tuple[str, str], UITextMapping] = {}
          self._load_configurations()

      def _load_configurations(self):
          """Load all configuration assets and build lookup tables."""
          for guid, config in self.CONFIG_ASSETS.items():
              asset = self.assets.get(guid)
              if asset is None:
                  continue

              base_path = config['path']
              for dataset_name, text_path_template in
  config['mappings'].items():
                  # Get the dataset to iterate over its literals
                  dataset = self.assets.cache.datasets.get(dataset_name)
                  if dataset is None:
                      continue

                  # For each literal in the dataset, extract text/icon
                  for literal in dataset.literals:
                      text_path = text_path_template.format(literal)
                      full_path = f"{base_path}.{text_path}"

                      # Navigate to the text ID
                      text_attr = asset.find(full_path)
                      text_id = text_attr() if text_attr else None

                      # Try to find icon (usually at same level, replace 
  .Text with .Icon)
                      icon_path = full_path.replace('.Text',
  '.Icon').replace('.Name', '.Icon')
                      icon_attr = asset.find(icon_path)
                      icon_guid = icon_attr.guid if icon_attr and
  hasattr(icon_attr, 'guid') else None

                      # Store mapping
                      key = (dataset_name, literal)
                      self.mappings[key] = UITextMapping(text_id=text_id,
  icon_guid=icon_guid)

      def get_ui_text(self, dataset_name: str, literal: str) -> 
  UITextMapping | None:
          """Look up UI text mapping for a dataset literal."""
          return self.mappings.get((dataset_name, literal))

  ---
  Advantages of This Approach

  1. Minimal Hardcoding: Only need to specify:
    - Which configuration assets to load (3 GUIDs)
    - Path templates for each dataset (simple string patterns)
  2. Automatic Discovery: Iterates over dataset literals automatically, no
  need to hardcode every buff type
  3. Extensible: Easy to add new configuration assets by adding entries to
  CONFIG_ASSETS
  4. Type-Safe: UI text is attached directly to attributes, accessible via
  .ui_text_id
  5. Fallback-Friendly: Returns None if mapping doesn't exist, graceful
  degradation
  6. Performance: One-time loading at startup, fast dictionary lookups

  ---
  Edge Cases Handled

  1. Multiple Text Variants: Some buffs have context-specific text (e.g.,
  BuffConstructionCost has ShipyardText, RecruitmentText, SingleShipText,
  SingleTroopText)
    - Solution: Extend UITextMapping to include variants dict
  2. Missing Configurations: Not all dataset values may have UI text
    - Solution: Return None, let converters handle gracefully
  3. Nested Structures: Some configs use arrays (e.g.,
  BuffAdditionalNeedAttributes.Attributes.Population.Text)
    - Solution: Use more complex path templates with placeholders
